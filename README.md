# PhoneStore

A working Vietnamese electronics storefront built inside the existing ASP.NET Core MVC project. Customer and admin screens use SQL Server data; checkout creates real orders and updates inventory. Seed products, prices, specifications, and illustrations are demonstration data.

## Technologies and requirements

- .NET 10 SDK (verified with 10.0.402), ASP.NET Core MVC and Razor
- EF Core 10 SQL Server provider and migrations
- ASP.NET Core Identity with Admin and Customer roles
- Microsoft SQL Server, Windows Authentication
- Bootstrap 5, jQuery Validation and Chart.js 4.5.1, all served locally
- Visual Studio Community 2026 or a compatible .NET IDE; SSMS 2022 is useful for inspection
- PowerShell 7 for the optional integration test script

## Quick start

From `D:\Project\PhoneStore`:

```powershell
dotnet restore PhoneStore/PhoneStore.csproj
dotnet tool restore
dotnet ef database update --project PhoneStore/PhoneStore.csproj --startup-project PhoneStore/PhoneStore.csproj
dotnet run --project PhoneStore/PhoneStore.csproj --launch-profile https
```

Open **https://localhost:7280**. HTTP at http://localhost:5177 redirects to HTTPS. In Visual Studio, open `PhoneStore.slnx`, select the `https` profile and run.

The Development startup applies outstanding migrations and idempotently seeds roles, the admin account, three categories, six brands, and 15 sample products. Repeated launches do not duplicate this data. Production does not automatically migrate or seed the development account.

## Database configuration

`PhoneStore/appsettings.json` contains:

```text
Server=localhost;Database=PhoneStoreDB;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true
```

The Windows identity running the app or migrations must have permission to access SQL Server and create/update this database. SQL Server must be the local default instance. If your installation uses a named instance, update the connection string appropriately. The certificate trust option is for this local development environment.

### Migrations

The checked-in `InitialCreate` migration is the source of truth. Do not run `migrations add InitialCreate` again.

```powershell
# After intentionally changing the model:
dotnet ef migrations add DescribeYourChange --project PhoneStore/PhoneStore.csproj
dotnet ef database update --project PhoneStore/PhoneStore.csproj

# Regenerate the SQL script from migrations:
dotnet ef migrations script --idempotent --project PhoneStore/PhoneStore.csproj --output Database/PhoneStoreDB.sql

# Check whether model changes still need a migration:
dotnet ef migrations has-pending-model-changes --project PhoneStore/PhoneStore.csproj
```

`Database/PhoneStoreDB.sql` is generated by EF. Apply it to a selected `PhoneStoreDB` database if using SSMS; the normal `database update` command also creates the database. The SQL script creates the schema; application startup seeds demo data.

### Tables

Business tables: `Categories`, `Brands`, `Products`, `ProductImages`, `Orders`, `OrderDetails`.

Identity tables: `AspNetUsers` (including FullName, Address, CreatedAt and IsActive), `AspNetRoles`, `AspNetUserRoles`, `AspNetUserClaims`, `AspNetUserLogins`, `AspNetUserTokens`, `AspNetRoleClaims`.

EF tracks schema versions in `__EFMigrationsHistory`. Products reference categories and brands; images reference products. Orders reference users and contain order details referencing products. Restrictive foreign keys preserve order history. Slugs, order codes and checkout tokens have unique indexes. Money is stored as `decimal(18,2)`; stock has a SQL nonnegative constraint.

## Customer features

- Responsive home with featured, new, sale products and brand navigation
- Database search by product name, brand and description
- Combinable category/brand/price/stock/sale filters; five sort options
- Server-side pagination, preserving filters in page links
- Unique slug detail routes, product gallery, specifications and stock availability
- Register, login, POST logout, profile editing and password change
- Anonymous session cart: add, update quantities, remove and clear
- Authenticated COD checkout, prefilled address and server-calculated summary
- Order history, ownership-protected details, pending-order cancellation
- Vietnamese currency and UTC dates displayed at UTC+7

## Admin features

- Actual database counts, completed revenue, pending orders and low-stock count
- Monthly order/revenue charts with an accessible table of the same data
- Product search, brand/status filters, pagination, create/edit/detail and soft deactivation
- Product specifications and multiple uploaded images; remove existing images
- Category and brand create/edit/activate/deactivate
- Order search by code/receiver/customer, status filters, date sorting, detail and status updates
- Customer list/search, role display, account deactivation/reactivation
- Admin accounts and the current administrator cannot be deactivated through user management

## Business rules and security

- Identity hashes passwords; minimum eight characters with upper/lowercase, digit and symbol. Failed logins are locked after five attempts for ten minutes.
- All admin controllers require `[Authorize(Roles = "Admin")]`. Checkout, profile and customer orders require authentication.
- Global `AutoValidateAntiforgeryToken` protects every state-changing MVC form. Mutation endpoints are POST-only. Views HTML-encode descriptions and user input.
- Dedicated input models prevent role, order status, price snapshot and other protected-field overposting.
- Carts store only product IDs and quantities. Prices and stock are loaded from SQL Server.
- Checkout uses a transaction and product row versions. A competing stock change rolls back the entire order, including all stock deductions. The database also rejects negative stock.
- A unique checkout token prevents duplicate submission from creating two orders. Old checkout pages are invalidated when a new checkout session starts.
- Order details store product-name and unit-price snapshots. Later product edits do not change historical totals.
- Allowed transitions: Pending → Confirmed → Shipping → Completed, or Pending → Cancelled. Customers may only cancel their own pending order. Cancellation and stock restoration are transactional; row versions prevent repeated restoration.
- Admin product edits carry row versions, so stale forms cannot overwrite stock reduced by a checkout.
- A deactivated customer is rejected on the next authenticated request, including an already logged-in session.
- Uploads accept JPG/JPEG, PNG and WebP only, at most 5 MB each and eight per submission. Extensions and file signatures are checked; names are GUID-generated. Only generated upload paths can be removed. SVG is not accepted as an upload. Checked-in local SVG illustrations are trusted application assets.
- No physical product/category/brand deletion is exposed. Inactive records preserve history and disappear from public catalog queries.

## Troubleshooting

- **SQL Server connection fails:** check the local SQL Server service, instance name and Windows login permissions. Run `sqlcmd -S localhost -E -C -Q "SELECT @@VERSION"` or connect in SSMS. A restricted execution environment may need explicit local SQL access.
- **Migration failure:** check SQL permissions and the full error. Run `dotnet ef migrations list --project PhoneStore/PhoneStore.csproj`. Do not manually create tables or delete migration history to hide an error.
- **Database already exists:** EF applies only missing migrations. If unrelated tables with the same names already exist, use a separate database name or reconcile its schema rather than deleting data.
- **dotnet-ef missing:** run `dotnet tool restore` from the repository root. `dotnet-tools.json` pins the compatible local tool.
- **NuGet restore fails:** allow access to `api.nuget.org`; retry restore after checking proxy/firewall settings.
- **Certificate issue:** run `dotnet dev-certs https --trust` and restart the browser. Use the `https` launch profile.
- **Login fails:** confirm Development seeding has run, the account is active, and the password is correct. Wait ten minutes after repeated failed attempts. Admin credentials are not automatically seeded in Production.
- **Stock changed while editing/ordering:** reload the product/cart. This is an intentional concurrency safeguard.
- **Port in use / executable locked during build:** stop the previously running PhoneStore instance before building or restarting.

## Scope and limitations

COD is the only payment method; there is no external gateway, email delivery, password-reset email, shipping integration, tax engine, coupons, reviews or favorites. Brand logo upload is optional and not included. The session cart is in memory on one server and resets on application restart; production scale-out would need shared session storage. Image validation uses signatures and size limits, not a full image decoder/re-encoder or malware scanner. Local upload files need durable storage/backups in a deployed environment. Demo illustrations are not photographs, and specifications are explicitly fictional. This is a complete local student-project core, not a production fulfillment system.
